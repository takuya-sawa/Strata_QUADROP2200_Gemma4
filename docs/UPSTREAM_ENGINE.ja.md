# 本家エンジンの統合

本家 Strata `v0.2.22` のエンジン (`0.1.69`, commit `b28ca95e3e6847f2d5e317994f253b66716deeaa`) を、このフォークのルートエンジンへ統合しました。別ディレクトリに置いただけの状態ではありません。ライセンスはリポジトリルートの `LICENSE` を参照してください。

## フォーク固有の実装

既存の Gemma 4 / DeepSeek-V4.1 実装と、それらに必要なビルド・実行経路は保持しています。本家 v0.2.22 にはこのフォークの `strata-gemma4` サーバーターゲットがないため、Gemma 4 の分岐を本家側のモデル実装で置き換えてはいません。

この統合はソースとビルド設定に対する変更です。稼働中の `build-local-p2200/strata` や Web UI/API は置き換えていません。

## P2200 での確認結果 (2026-11-26)

本家のソースには Pascal `sm_61` 向けの実験的な CUDA 12 ビルド経路があります。統合後のツリーを CUDA 12.2・gcc-12・`-DSTRATA_EXPERIMENTAL_SM60=ON -DCMAKE_CUDA_ARCHITECTURES=61` でビルドし (`strata` 0.1.69 と `strata-gemma4`)、Gemma 4 26B-A4B Q4_0 を別ポートで起動して測定しました。

| 項目 | 統合後 | 従来ビルド (2026-11-25) |
| --- | --- | --- |
| 短文 100 token の出力 (6 回) | 5.4〜12.5 token/s、後半 4 回は 9.0〜12.5 | 中央値 10.25 token/s |
| 入力 1,898 token の初回処理 | 64.8 秒、29.2 token/s | 67.6 秒、28.0 token/s |
| 同じ入力の再送 (KV 再利用) | 0.10 秒 | 0.09 秒 |

日本語の応答と KV 再利用は正常でした。速度は従来ビルドと同等で、本家エンジンへの更新で Gemma 4 が速くなったわけではありません。nvcc 12.2 では `iq_kernels.cu` の `DotG` に既定の実装を足さないとコンパイルできません。

本家由来のソース更新は以後このルートツリーへ反映し、別の `upstream-engine-v0.2.22/` スナップショットは持ちません。
